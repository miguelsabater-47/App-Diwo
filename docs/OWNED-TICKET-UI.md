# Owned ticket detail

The personal `/ticket` overview stays QR-free. Each ticket links to `/ticket/[id]`, whose dynamic server page reads one owner-scoped `public.read_owned_ticket(target_ticket)` RPC row through the signed Supabase session. The current database role is checked before the call and after the read; the safe projection drops every unrecognized column. Missing and non-owned tickets share the framework not-found response. Authentication and dependency failures do not synthesize ticket or QR data.

Only a valid ticket with a persisted lowercase 64-character hex token receives a locally generated QR data URL. The raw token is not passed to a client component or written to a URL, storage, logs, analytics, or a third-party QR service. Used and revoked history contains no QR and has no export actions. Every image export/share performs a fresh owner-only GET first; a previously saved image is a snapshot and is not a claim that a scanner accepts it.

The detail and exported PNG/JPG prominently label technical fixtures. Visible event data uses the agreed Europe/Madrid timezone and generic public location only; the exact address is not included. Native file sharing is used when available; otherwise share falls back to download for manual sharing. On 2026-10-13 Miguel confirms the four retained technical tickets, signed detail/QR/disclaimer, correct PNG/JPG downloads and actual Chrome selector opening from one icon click. This is user-reported evidence, not independent hosted permission/data-invariant verification, successful delivery to a recipient, complete rendered desktop/mobile/focus/navigation/console review or physical-device QR readability. Those broader checks remain pending.

The retained technical event is recognized by its exact ID and slug and keeps its fictional location. Normal tickets accept only the approved generic location, EUR and 500-cent price. Image exports include the ticket card, not interactive controls. Before capture, the latest valid owner response must match the requested ticket, its QR replaces the displayed QR, and image decoding/fonts finish. Sharing uses one icon control with an accessible label and native title tooltip. One click reads the current ticket, prepares the PNG and invokes native sharing automatically: no prepared-file state, second preparation click or fourth action exists. Only the active action shows a loading indicator. Browser transient activation may expire during slow preparation; a NotAllowedError falls back to downloading that freshly generated PNG with an explanatory status, without retrying native sharing. Missing file-sharing support also downloads the image. A native share promise pending for 15 seconds releases application controls and offers manual download; this does not cancel the operating-system share sheet. Late completion cannot change application state. Cancelling native sharing does not automatically download a file. PNG/JPG downloads and fresh owner checks are unchanged. Chrome one-click selector opening is user-confirmed; other-device/rendered checks remain pending.

Dependencies are pinned locally to `qrcode@1.5.4` and `@types/qrcode@1.5.5`; encoding stays on the server with four white quiet-zone modules and black QR modules. `npm test` includes model/export tests and the SQL validation suite includes the owner RPC tests. No package install scripts were executed.
